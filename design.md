# 2. Features for the first version

I'd keep the MVP focused on six core modules.

| Module               | What it does                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------------ |
| Dashboard            | Shows pending quotes, follow-ups due, accepted quotes, and estimated value of open opportunities |
| Quote management     | Creates quotes manually or imports information from PDFs                                         |
| Customer management  | Stores customer names, emails, job details, and quote history                                    |
| Follow-up automation | Sends scheduled, personalized email reminders                                                    |
| Reply handling       | Pauses follow-ups when a customer replies and alerts the contractor                              |
| Reports              | Tracks follow-up activity, quote outcomes, and confirmed revenue                                 |

### PDF upload

When a contractor uploads an estimate, the system should:

1. Extract text from the PDF.
2. Identify the customer name, email, estimate number, amount, and job description where available.
3. Display the extracted information for confirmation.
4. Let the contractor correct missing or inaccurate details.
5. Save the quote and allow the contractor to activate its follow-up sequence.

Some PDFs are scanned images rather than text-based documents, so you'll need OCR as a fallback. Never send an email using unconfirmed contact details extracted from a document.

### Manual quote entry

Contractors should also be able to enter:

- Customer name and email
- Quote amount
- Job description
- Quote date and expiration date, if applicable
- Notes
- Current status
- Follow-up schedule

Manual entry is important because some contractors will not want to upload customer documents.

# 3. How email follow-up will work

For the first version, I recommend a configurable sequence like this:

| Timing      | Action                                                                     |
| ----------- | -------------------------------------------------------------------------- |
| Day 0       | Contractor adds and approves the quote                                     |
| Day 2       | First follow-up email                                                      |
| Day 5       | Second follow-up if there is no response                                   |
| Day 9       | Final scheduled reminder                                                   |
| After Day 9 | Stop automated messages and leave the quote available for manual follow-up |

These are suggested defaults, not mandatory rules. Contractors should be able to change the schedule and disable reminders for individual quotes.

Each email should include the customer's name, the relevant job or estimate reference, a simple question, and a way to contact the contractor.

Reply handling is an important technical requirement. Sending email is straightforward; reliably detecting replies is a separate capability. We should choose an email provider and implement inbound email events or a suitable reply-tracking mechanism before promising automatic reply detection. Until that is configured, the product should not claim it can detect every reply.

### Why background jobs matter

You shouldn't rely on a browser being open or a user being logged in to send scheduled emails.

The background job system should:

- Find quotes with follow-ups due.
- Check the quote is still eligible.
- Check suppression, consent, and unsubscribe status.
- Send the email.
- Record the delivery result.
- Schedule the next step.
- Retry temporary failures safely without sending duplicates.

Use idempotency protections so that a retry cannot accidentally send the same reminder twice.

# 5. Database design

Start with these tables:

- `organizations` — contractor businesses and their settings.
- `users` — authenticated users and their organization membership.
- `customers` — customer contact details.
- `quotes` — quote amount, job description, dates, and status.
- `quote_documents` — uploaded PDF metadata and storage location.
- `follow_up_sequences` — reusable follow-up schedules.
- `follow_up_steps` — individual messages and timing rules.
- `scheduled_follow_ups` — pending jobs and execution status.
- `email_events` — sent, delivered, bounced, and other provider events.
- `conversations` — inbound and outbound customer communications.
- `activity_logs` — changes made by users and automation.

Every business-owned record must be scoped to the correct organization. Use database access controls, private document storage, and server-side authorization to prevent one contractor from accessing another contractor's data.

# 6. What to leave out of the MVP

Avoid building these features initially:

- SMS and AI voice calling
- Full CRM functionality
- Dispatching and technician management
- Invoicing and payment processing for contractors
- Complex integrations with every existing contractor platform
- AI-generated negotiation or discount decisions
- A customer-facing mobile app

You can add these later if paying customers request them.

# 8. Your development roadmap

A realistic initial roadmap is around four weeks for a focused MVP, depending on your experience with the services and how much you use AI coding tools.

Week 1 — Foundation

- Set up the application, authentication, database, and organization model.
- Build the dashboard and customer/quote management.
- Implement manual quote entry.

Week 2 — PDF and email

- Add PDF upload and extraction.
- Build the quote confirmation screen.
- Integrate email delivery and templates.

Week 3 — Automation

- Implement scheduled jobs and follow-up sequences.
- Add status checks, unsubscribe handling, and duplicate-send protection.
- Implement reply tracking and notifications.

Week 4 — Testing and launch

- Add reporting and billing.
- Test email failures, bounced addresses, duplicate jobs, and invalid PDFs.
- Test organization-level data isolation.
- Onboard a small number of pilot customers.

## The most important business decision

Although we're supporting three industries, I'd still test the product with a small group of contractors first. Roofing, HVAC, and plumbing businesses can share the same core application, but their quote workflows and messaging may differ.

Your first milestone should be five contractors using the product on real quotes, not a large feature set.

Once they demonstrate that they will pay for it, you can decide which integrations, AI features, and trade-specific workflows deserve investment.
